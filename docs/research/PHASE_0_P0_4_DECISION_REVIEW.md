## Decision

P0.2 is complete for the owner's explicitly accepted transition to P0.3 only; it is not an all-gates pass. P0.3's disposable Pages route proof is complete under the revised evidence standard: static artifact identity is observed, Pages documents static-file routing and CDN/Tiered Cache delivery, the `/b/*` path is outside configured Function routes, and a same-window positive control plus absent profile events establish no Pages Function invocation for the observed requests. This supports no NexTap application-origin access on the observed static path. It does not establish an observable HIT at a particular cache tier for any individual response. Phase 0 remains incomplete: the physical Android/mobile-network gate is unmet and blocking; the dedicated synthetic-card journey is unverified; and proposed performance thresholds remain unvalidated for target Cloudflare delivery. Legacy browser samples also miss the proposed cold LCP, request-count, and mobile-image budgets, but they are not target-delivery measurements. Do not describe the revised evidence standard as a delivery change or Phase 0 pass.

## Edge And Origin Evidence Path

Cloudflare's official [Serving Pages documentation](https://developers.cloudflare.com/pages/configuration/serving-pages/) states that Pages serves an HTML file when its path matches the request, that uploaded static assets are automatically served from Tiered Cache, and that assets stay cached until a deployment but may disappear earlier. This documents the platform behavior for static assets. The local fixture, deployed body/hash, `_routes.json`, declared bindings/source, and same-window positive-control tail show that the observed `/b/*` response follows that static Pages path without a Pages Function. Taken together, these signals establish no NexTap application-origin request for the observed requests (for example Vercel/Next.js); Cloudflare's internal asset storage is outside that definition. The evidence does not show whether a particular response was an edge cache HIT. No `CF-Cache-Status` or `Age` signal is required for this Pages route, and `CF-Ray`, matching hashes, source/config inspection, or absent log entries alone must not be labeled as a cache HIT.

Recommendation: accept the P0.3 Pages route evidence under the owner's revised evidence standard. Preserve the delivery contract: warm `/b/{slug}` remains static Pages delivery, invokes no Pages Function/Worker, accesses no D1/KV/Supabase, and makes no request to a NexTap application service. Do not add a cache-status/Age requirement, plan purchase, DNS change, or telemetry project to make an individual cache HIT observable. Keep the narrower limitation explicit: this evidence does not attest to a particular cache tier serving a particular response as a HIT. The no-origin inference is about NexTap application services; it does not mean Cloudflare avoids its internal asset storage.

The following owner decisions remain unresolved and are separate from P0.3 route evidence:

1. Resolve the `has_menu` discrepancy between the PRD's profile-link contract and the plan's statement that Menu-enabled profiles are future work; preserve this difference until the product owner decides whether to retain, defer/update, or fixture the profile contract.
2. Choose a finite old-slug alias retention duration or indefinite retention before automatic expiry is implemented. Keep every previous URL working through migration and cutover. The synthetic alias publication run does not choose storage semantics or retention policy.
3. Physical Android remains blocking and synthetic-card evidence remains required under the current Phase 0 exit rubric. The owner's unavailability statement does not authorize an exception. Change the PRD/exit criteria only through an explicit owner-approved exception; the existing P0.2 transition acceptance is not such an exception.
4. Confirm whether the PRD's assumed $5/month Workers Paid plan and $10/month total recurring-spend review threshold remain appropriate. These are planning assumptions, not observed current or future cost; do not buy a plan to obtain cache headers. The existing proof uses the Pages custom-hostname path and does not prove direct R2 custom-domain or Workers Route behavior. See plan `:34-35,86-94,98-105` and PRD `:257,261`.

# Cloudflare Workers Platform Evidence

Research checked against official documentation on **2026-10-30**. Quotas and prices below are published plan values, not a forecast for NexTap usage. Runtime and adapter documentation can change; keep framework, adapter, Wrangler, and lockfile versions explicit, and advance the Workers compatibility date only as a reviewed runtime upgrade.

## Workers runtime and compatibility

- Workers Free currently allows 100,000 requests/day, 10 ms CPU per request, 128 MB memory, and 50 subrequests per request. Workers Paid has no request-count limit, up to 5 minutes CPU, the same 128 MB memory, and up to 10,000 subrequests. These are platform limits, not a latency or throughput guarantee. [Cloudflare Workers limits](https://developers.cloudflare.com/workers/platform/limits/)
- `compatibility_date` pins the runtime behavior and compatibility flags opt into selected changes. Cloudflare’s Node compatibility page says Workers with dates from **2026-08-04 onward** enable the Node compatibility behavior by default; new configs using those dates should omit `nodejs_compat` flags. Earlier dates from 2024-09-23 through 2026-08-03 need the flag. Node support is a subset: APIs may be fully or partially implemented, or exposed as importable stubs whose methods throw. [Compatibility dates](https://developers.cloudflare.com/workers/configuration/compatibility-dates/) · [Node.js compatibility](https://developers.cloudflare.com/workers/runtime-apis/nodejs/)
- OpenNext’s setup documentation still shows an explicit `nodejs_compat` flag and requires a date on or after 2024-09-23. Cloudflare’s current OpenNext adapter guide uses today’s date and the flag in its example, while Cloudflare’s Node runtime docs say to omit the flag for dates on or after 2026-08-04. Treat the adapter example as a minimum/older compatibility recipe, not proof that the 2026 runtime defaults are identical. Pin one tested date in Worker config; update it deliberately with the adapter and runtime tests. [OpenNext setup](https://opennext.js.org/cloudflare/get-started) · [Cloudflare OpenNext adapter](https://developers.cloudflare.com/workers/framework-guides/web-apps/opennext/) · [Cloudflare Node.js compatibility](https://developers.cloudflare.com/workers/runtime-apis/nodejs/)

## Next.js adapter and Next.js 15 behavior

- Cloudflare’s Next.js guide, last updated 2026-08-25, recommends **vinext** as its default Workers path, describes it as beta, and documents `vinext init` for existing Next.js 16 apps. The same guide retains OpenNext for an existing app that cannot yet migrate because of a compatibility gap. The recommendation is therefore not evidence that vinext supports this Next.js 15 application. [Cloudflare Next.js guide](https://developers.cloudflare.com/workers/framework-guides/web-apps/nextjs/)
- Cloudflare’s OpenNext adapter guide requires manual adapter configuration and says **Node.js middleware introduced in Next.js 15.2 is not yet supported**. OpenNext’s own setup guide says its Edge runtime is not supported and asks apps to remove `export const runtime = "edge"`. Its known-issues page documents a local-development warning for internal caching Durable Objects; those bindings should work in production but need a separate Worker for local development. [Cloudflare OpenNext adapter](https://developers.cloudflare.com/workers/framework-guides/web-apps/opennext/) · [OpenNext setup](https://opennext.js.org/cloudflare/get-started) · [OpenNext known issues](https://opennext.js.org/cloudflare/known-issues)
- In Next.js 15 App Router, route handlers live in `app/**/route.ts`, use Web `Request`/`Response`, and support standard HTTP methods. `GET` handlers are uncached by default in v15 unless caching is opted into. Route segments default to the Node.js runtime; Edge has fewer APIs and does not support native Node APIs or ISR. Middleware runs before route rendering and defaults to Edge; Node middleware is stable from 15.5 (experimental in 15.2), but the Cloudflare OpenNext adapter limitation above still applies. [Route handlers](https://nextjs.org/docs/15/app/getting-started/route-handlers-and-middleware) · [Route segment config](https://nextjs.org/docs/15/app/api-reference/file-conventions/route-segment-config) · [Edge runtime](https://nextjs.org/docs/15/app/api-reference/edge) · [Middleware](https://nextjs.org/docs/15/app/api-reference/file-conventions/middleware)
- OpenNext setup examples install `@opennextjs/cloudflare@latest` and `wrangler@latest`. For a reproducible migration, resolve and test exact versions, commit the lockfile, and record the Worker compatibility date rather than treating `latest` or a moving date as a pin. Cloudflare’s compatibility date controls runtime behavior; it does not pin the adapter or framework package versions. [Cloudflare OpenNext adapter](https://developers.cloudflare.com/workers/framework-guides/web-apps/opennext/) · [Compatibility dates](https://developers.cloudflare.com/workers/configuration/compatibility-dates/)

## R2 behavior and published pricing

- R2 object upload followed by read, metadata update, delete, and object listing are strongly consistent globally. Permission changes for a new or updated R2 API key can take up to about one minute to propagate globally. Public objects served through a caching custom domain have relaxed consistency while cached; deletion or update may not be visible until the cache is purged or expires. [R2 consistency model](https://developers.cloudflare.com/r2/reference/consistency/)
- Current Standard storage pricing is $0.015/GB-month, $4.50 per million Class A operations, and $0.36 per million Class B operations; Internet egress is free. The monthly Standard free tier includes 10 GB-month storage, 1 million Class A requests, and 10 million Class B requests. The free tier does not apply to Infrequent Access, which also has retrieval charges and a 30-day minimum storage duration. [R2 pricing](https://developers.cloudflare.com/r2/pricing/)
- An R2 object can be up to 5 TiB; single-part upload is limited to 5 GiB, multipart upload to 4.995 TiB and 10,000 parts. The managed `r2.dev` public endpoint is for testing and may throttle requests and bandwidth; use a custom domain for production delivery. [R2 limits](https://developers.cloudflare.com/r2/platform/limits/)

## Supabase Auth, SSR, and plan quotas

- Supabase SSR uses cookie-backed clients from `@supabase/ssr`. For Next.js 15, middleware refreshes expired tokens because Server Components cannot write cookies; refreshed cookies must be propagated to both the request and response. Supabase recommends `getClaims()` to verify identity server-side and warns against trusting `getSession()` for that purpose. The `supabase-js` README explicitly lists Cloudflare Workers as a supported runtime, but that is not certification of a particular Next.js/OpenNext combination. [Supabase SSR guide](https://supabase.com/docs/guides/auth/server-side/nextjs) · [`supabase-js` Cloudflare support](https://github.com/supabase/supabase-js#cloudflare-workers)
- Supabase currently lists Free at $0/month and Pro from $25/month. Free includes 50,000 MAUs, 500 MB database size, 5 GB egress, 5 GB cached egress, 1 GB file storage, unlimited API requests, and two active projects. Pricing summarizes that Free projects can pause after one week of inactivity; the project-pausing guide defines this as low user database activity over seven days, with no precise threshold, and documents a 90-day restore window. Pro includes 100,000 MAUs, then $0.00325/MAU. These are published plan limits, not evidence of this project's tier or actual usage. [Supabase pricing](https://supabase.com/pricing) · [Project pausing](https://supabase.com/docs/guides/platform/free-project-pausing)
- Supabase's database-backup guide says automatic daily backups are available on Pro, Team, and Enterprise; Pro projects can access the last seven days. Free projects are advised to export with `supabase db dump` and keep off-site backups. A database backup alone is not a complete Storage backup: Storage file metadata lives in Postgres, while the files themselves need separate handling; Supabase documents separate object-download and storage-migration steps. [Database backups](https://supabase.com/docs/guides/platform/backups) · [Download Storage objects](https://supabase.com/docs/guides/storage/management/download-objects) · [Backup and restore](https://supabase.com/docs/guides/platform/migrating-within-supabase/backup-restore)
- Auth's built-in email provider allows 2 emails/hour; default SMS limit is 30/hour, and rate-limited endpoints return HTTP 429. Supabase pricing, project-pausing, and backup pages were checked on 2026-10-30; these public plan details are mutable and should be rechecked against the live plan before launch. [Auth rate limits](https://supabase.com/docs/guides/auth/rate-limits)

## Hostinger registrar nameserver migration

- Hostinger’s domain-pointing guide says changing nameservers at the registrar delegates all DNS to the destination nameserver operator; its DNS editor is available only while using Hostinger nameservers. For a move to Cloudflare DNS, prepare/copy the required web, mail, verification, and other records in the Cloudflare zone, then replace the registrar’s nameservers with the two values Cloudflare assigns. Cloudflare’s full-setup guide says to disable DNSSEC at the registrar before changing nameservers and re-enable it only after the zone is active and Cloudflare DNSSEC is configured. After delegation, manage records at Cloudflare. Hostinger says DNS changes can take up to 24–48 hours to propagate globally. No account-specific nameserver values or live zone were inspected. [Hostinger domain pointing](https://docs.hostinger.com/domains/pointing.md) · [Hostinger DNS management](https://docs.hostinger.com/domains/dns.md) · [Cloudflare full setup](https://developers.cloudflare.com/dns/zone-setups/full-setup/setup/)

## Source limitations

All sources above are public first-party documentation accessed 2026-10-30. Adapter compatibility tables, plan prices, quotas, and backup terms are mutable; Supabase pricing, project-pausing, and backup pages do not display a last-updated date. No credentials, hosted resources, account dashboards, project usage, backup status, or live DNS settings were accessed. The available official evidence does not certify full NexTap route-by-route parity on OpenNext, validate vinext against this Next.js 15 codebase, or confirm exact account-specific DNS values; those require repository testing or account-owner verification.

## Agent Hooks and Guardrails

Official references checked 2026-11-05:

- [Codex hooks](https://learn.chatgpt.com/docs/hooks) documents `PreCompact`, `PostCompact`, `SessionStart`, `PreToolUse`, `PostToolUse`, and `Stop`. Plain stdout from `PreCompact` is ignored; its JSON output does not provide the event's context-injection field. After compaction, `SessionStart` with `source=compact` runs before the next model request, including automatic mid-turn compaction, and can return `additionalContext`. Use `PreCompact` to write a durable note and `SessionStart` to load only that note. `PostToolUse` occurs after the action and cannot undo it.
- [Claude Code hooks](https://code.claude.com/docs/en/hooks) documents `PreCompact` and `PostCompact`. `PreCompact` receives the trigger and optional user-supplied custom instructions; its `systemMessage` and `continue` fields are discarded. `PostCompact` receives the generated `compact_summary`, but its `systemMessage` and `continue` fields are also discarded and it has no decision control. Use these hooks to persist a compact, task-specific recovery packet and summary. Inject the packet only through an event/output the current Claude Code version documents for context injection; test the next-request and automatic mid-turn behavior before claiming Codex parity.
- [Claude Code memory](https://code.claude.com/docs/en/memory) and [OpenAI prompt engineering](https://platform.openai.com/docs/guides/prompt-engineering) support scoped, relevant context and authoritative instructions. A compact task packet is a recovery aid, not a substitute for source checks.
- GitHub issue tracking can hold tasks/dependencies when implementation is approved: [About issues](https://docs.github.com/en/issues/tracking-your-work-with-issues/about-issues).

The owner asked for useful notes across compaction, including decisions already settled, files already reviewed, current worktree/base, edits/checks, unresolved questions and the next exact action. Store that as a small durable continuation packet, not a transcript. Keep secrets and customer data out. Hooks cannot guarantee a verbatim summary survives compaction; acceptance must demonstrate the saved packet is restored and stale claims are checked against their linked source.

**Current repository pattern:** .github/pull_request_template.md and scripts/ci/self-review.mjs define diff, exact-SHA, tests, security, rollback, high-risk and release-evidence checks. The October 15 handoff says a workflow invokes the evaluator, but that workflow is not in this clean base. Verify the invocation and output artifact in a future CI run before treating it as an automated guardrail. The script is a pull-request review gate, not an agent lifecycle hook and not a codebook conformance checker.

| Hook/control | Use in NexTap | Limit |
| --- | --- | --- |
| Reactive review skills | Invoke `clean-code-guard` on production-code diffs, `test-guard` on test diffs, and `docs-guard` on docs changes. The Skills README recommends a second-pass review; the skills themselves require no executable. | They are judgment guidance, not hooks, lint, tests, file/dependency gates, or proof of codebook compliance. Skip WP/Woo guards; NexTap's codebook and explicit behavior contracts win over generic advice. |
| Function-level guidance | `clean-code-guard` suggests a 20-line function target, a four-argument ceiling, and complexity/nesting limits. | These are skill-level review heuristics, not NexTap's agreed per-file budgets. Keep them advisory until the Phase 1 codebook accepts or adjusts them; do not launch a mechanical rewrite to satisfy them. |
| Session start / compact recovery | Load only the active task packet, owner decisions and current continuation note. Codex documents `SessionStart(source=compact)` before the next request. | Claude event timing differs; verify the current version's context-injection event. Always link authoritative files and recheck uncertain claims. |
| Pre-/post-compaction | Codex `PreCompact` writes the packet; `SessionStart(source=compact)` restores it. Claude `PreCompact` records the task note and `PostCompact` can capture its generated summary. | Codex plain PreCompact stdout is ignored. Claude discards `systemMessage` and `continue` on both compact events; do not promise verbatim injection. |
| Subagent context and completion | Where supported, pass the short task packet and codebook link on `SubagentStart`; on `SubagentStop`, collect changed paths, checks and unresolved items for the parent review. | Events differ by platform and do not prove child work followed rules; the parent still reviews the diff and CI evidence. |

| Stop / task completion | Ask for codebook, test, mutation-survivor, dependency, diff, docs and continuation-note evidence. | A reminder is not proof. The same commands and evidence must be checked in CI/review. |
| Platform-neutral CI | Enforce lint/typecheck/tests, import boundaries, changed-file budgets, dependency-change review and focused mutation ratchets. Use Knip as a candidate report and a registry deprecation check on dependency changes. | Baseline legacy findings first; no automatic dependency/code deletion and no broad mutation score without evidence. |

The user supplied the exact package: [`amElnagdy/guard-skills`](https://github.com/amElnagdy/guard-skills). Installation copies skills; updates do not flow into a project automatically. For NexTap, select only the three applicable guards and scope installation to the intended agent/project after Phase 1 implementation is approved. Do not install `wp-guard` or `woo-guard`.

Prefer first-party hook contracts and NexTap-owned small adapters; revisit those projects only if a specific behavior remains missing and their source, license and security model pass review.

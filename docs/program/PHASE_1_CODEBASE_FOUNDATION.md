## Goal and Exit

Make migration-relevant parts of NexTap easier to understand, change, test and operate without broad rewrites. Establish an evidence-backed responsibility map, practical codebook, targeted mutation baseline, changed-file budgets and agent continuity checks; then complete a small behavior-preserving refactor.

Exit requires:

- Current routes, data flows, database/security contracts, runtime boundaries, tests and ownership map are reviewed and linked.
- One reviewed codebook defines module placement/import/runtime rules and practical add/remove/deprecation guidance; AGENTS.md points to it instead of duplicating it.
- High-risk module mutation baseline and survivors are recorded. Changed modules meet the agreed ratchet or have explicitly reviewed survivors.
- Changed files follow per-kind budgets, import boundaries and dependency rules, with reviewed exceptions for legacy overages.
- Existing lint, typecheck, unit, SQL/migration, concurrency, production build and affected browser journeys pass. No claim of Cloudflare compatibility is made in this phase.

## Proposed File Budgets

These are initial review budgets for Phase 1 to confirm against the source map; they are not a command to split every over-budget file. Count physical lines consistently in one check. Existing overages warn; a changed overage blocks unless its review exception states why splitting would reduce clarity or behavior safety.

| File kind | Proposed maximum | Existing treatment |
| --- | ---: | --- |
| Route, page, layout, route handler or server action | 250 lines | Warn on baseline overages; changed overage requires a scoped extraction or exception. |
| Reusable UI component/module | 250 lines | Same rule; consider cohesion, state ownership and accessibility before splitting. |
| Domain/workflow module | 300 lines | Same rule; keep invariants together when separation would weaken the contract. |
| Unit, integration or browser test file | 500 lines | Review setup reuse and behavioral grouping; do not split only to satisfy count. |
| Generated, migration, lock, snapshot, fixture, config and documentation files | Excluded from generic count | Apply format-specific checks; review generated source and migrations by their own contracts. |

If baseline results show these budgets harm cohesion or create mechanical fragments, record revised per-kind limits before enforcing them. No file may be deleted or split based on line count alone.

## Agent Hooks and Engineering Gates

CI is the authority for mergeable quality. Hooks should call the same deterministic scripts, stay fast and fail closed only for clear safety boundaries.

| Concern | CI / repository rule | Optional agent adapter |
| --- | --- | --- |
| Context continuity | Canonical PRD, phase packet, AGENTS.md and source docs remain authoritative. | Session start reads only the task packet and current continuation note. Before compaction, save a concise continuation record; after compact, restore that record. Do not preserve raw transcript or imply hook stdout is injected verbatim. |
| Destructive or environment-sensitive operations | Explicit worktree/branch/env checks and protected CI workflows. No Production resource or secret use in Phase 1. | Pre-tool hook can block reset/clean/push, wrong-worktree writes, Production environment access, or secret output when the task policy forbids them. Match active authorization and do not block normal local edits. |
| Codebook and boundaries | ESLint/import-boundary checks, tests and CI; no cross-runtime or private-module imports. | Pre/post-edit checks may run targeted lint or report likely violations. A review reminder can check codebook, file budget and evidence before stopping. |
| File budgets | Per-kind baseline report, warning for legacy files, changed-file gate with documented exception. | Report budget result for edited files; line count is a review signal, not an automatic refactoring instruction. |
| Dependencies and dead code | Audit and lockfile verification in CI; scheduled/report-only outdated/deprecated and Knip scans; owner review before removal. | On package changes, inspect deprecation/security and import graph. On task completion, surface unused candidates and affected tests; never delete automatically. |
| Tests and mutation | Existing CI tests plus focused Stryker ratchet on changed high-risk modules. | Run targeted checks on changed scope; request a full check only when the change crosses shared boundaries. |
| Reactive review skills | Use `clean-code-guard` for production-code diffs, `test-guard` for test diffs, and `docs-guard` for documentation diffs. | These are portable review instructions, not hooks or deterministic checks. Do not use the WordPress/WooCommerce guards; honor NexTap's codebook where generic advice conflicts. |

Relevant lifecycle behavior is summarized in the [research appendix](RESEARCH_APPENDIX.md). Codex ignores plain PreCompact stdout; the documented compact-recovery injection point is SessionStart with `source=compact`. Claude Code exposes the generated summary to PostCompact, but its output fields do not all enter the model context. Keep the continuation packet durable, small, secret-free and test the exact supported next-request injection path for the installed version.
